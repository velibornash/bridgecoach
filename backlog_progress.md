| Tests | `tests/integration/persistence-domains.test.ts` (12), `tests/e2e/persistence-journey.spec.ts` |

### Architecture decisions

- **`withUser(fn)`** wraps every private route handler, so ownership cannot be
  forgotten at a call site.
- **Ownership violations return 404, not 403**, so ids cannot be probed (§25/§27).
- **`src/lib/progression.ts` is the only writer of user XP.** `user.xp`,
  `user.level`, `user.streak`, `user.longestStreak` are derived caches recomputed
  from the `XPEvent` log. Streaks are computed from real event timestamps in UTC,
  not a stored counter.
- **AI: the user's message is committed BEFORE the provider is called**, so a
  provider failure never loses it. Only provider/model names and token counts are
  stored — never a key (asserted by a test).
- **`readMetric()` returns `null` for unknown/`manual` metrics.** `null` means
  "cannot be evaluated" and must never be coerced to 0 for unlock purposes.

### Bugs found and fixed while testing

| Bug | Cause | Fix |
|---|---|---|
| `completedSectionIds` erased on a repeat call | `upsert.update` blindly overwrote with `[]` when the field was omitted | Only write a field when the caller actually sent it (`isProvided()`) |
| "Perfect Score" unlocked on completed lessons | Seed mapped every non-streak achievement to `lessonsCompleted` | Added a per-category metric map; quiz achievements use `perfectQuizzes` |
| "Bridge Fanatic" / "Specialist" unlocked at 96 XP | Guessed `xp` as the metric for `mastery`/`special` thresholds (30 and 3) | Mapped to `manual`; `readMetric()` skips them |
| Seed did not repair wrong metrics | `upsert` used `update: {}` | Seed now also updates static definition fields |
| Dashboard showed `xp: 0` next to `lifetimeXp: 96` | Nothing wrote the `user.xp` cache | Progression engine recomputes it |
| Persistence tests failed after manual API testing | Tests asserted a *fresh* user but asserted against the shared dev user | Tests create their own throwaway user |

### Verified working

- 10 structured action rows → `AuctionStateMachine` replay → 4♠ by N

## Session 4 — Service layer + UI migration (58.2.2, in progress)

**Commit:** see git log for the session-4 commit (service layer rewrite)

### What changed

| Area | Before | After |
|---|---|---|
| `services/api.ts` | `simulateDelay` + `mockApiCall` faking latency and data | Real `apiFetch` / `apiFetchSafe`, `ApiRequestError` with real HTTP status, no fake latency |
| `services/lessonService.ts` | Read `mockData`, `saveLessonProgress` **discarded** its input | Reads `/api/content` + `/api/progress`; progress actually persists; `locked` is now a derived rule, not stored state |
| `services/quizService.ts` | Graded in the browser from the shipped answer key | Fetches from `/api/content` (answer key stripped) and submits to `/api/quiz-attempts` for server-side grading |
| `services/achievementService.ts` | `checkAchievementUnlocks` compared hardcoded ids and discarded results | Reads `/api/achievements`; `refreshAchievements()` recomputes on the server |
| `services/statsService.ts` | Returned `mockLearningStats` (28h, 78%, 12-day streak) | Adapts real `/api/stats` onto the UI's `LearningStats` shape |
| `services/challengeService.ts` | `mockDailyChallenges` with `Date.now()`-relative dates | Derived from seeded `daily` Missions — no invented dates |
| `services/authorStudioService.ts` | localStorage was authoritative | Database authoritative; localStorage is an offline cache only |
| Pages | `/learning-path`, `/lesson` read `mockData` directly | Load from services; **no `mockData` import remains in either** |
| `hooks/useApiResource.ts` | — | New shared hook giving every page explicit loading / error / empty states (§21) |

### Architecture decisions

- **ADAPTER, NOT A PAGE REWRITE (§22).** The statistics page renders 15+ fields
  of the legacy `LearningStats` interface, including `ProgressionMasteryWidget`,
  `SkillRadar` and a heatmap. Rather than half-migrate it, `getLearningStats()`
  maps the persisted shape onto the interface the UI already renders. The spec
  explicitly asks for this: "the service layer should shield the UI from
  persistence implementation details." `getPersistedStats()` exposes the raw
  shape for anything that wants it.
- **Integration tests call route handlers directly** instead of going over HTTP.
  jsdom cannot resolve relative `fetch` URLs, and calling the handler is faster
  and needs no dev server. The E2E journey still covers the real HTTP path.
- **`handleRoute` return type keeps `ctx` optional** so a test can invoke a route
  with only a `Request`, while Next.js still passes the context normally.

### Bugs found and fixed

| Bug | Cause | Fix |
|---|---|---|
| 15 tests failed with "Could not reach the server" | Services used relative `fetch` URLs, unresolvable in jsdom | Tests invoke route handlers directly |
| `Quiz` type name collision | New `LearningStats` in `statsService` clashed with the old one in `@/types` | Renamed to `PersistedLearningStats`; the service adapts to the old shape |
| Lint error: setState in effect (lesson page) | `epProgress` was stored in state but is a pure derivation | Computed with a plain expression, no state, no effect |
| Lint error: setState in effect (`useApiResource`) | `setLoading(true)` ran synchronously before the first `await` | State is only touched after an await |
| XP consistency test failed intermittently | Other test files mutated the shared dev user in parallel | That test now uses its own throwaway user |

**Commit:** see git log for the session-9 commit

### New routes

| Route | Purpose |
|---|---|
| `GET /api/quiz/check` | Grades ONE answer server-side and returns the verdict for that question only |
| `GET /api/certificates` | Derives one certificate per fully-completed course from persisted lesson progress |
| `GET/PATCH /api/notifications` | Feed derived from real activity; read-state stored as `Activity` rows so no extra table is needed |
| `GET /api/content` (earlier) | Serves courses/episodes/lessons with the answer key stripped |

### The quiz feedback conflict, and how it was resolved

The quiz UI must tell the learner immediately whether they were right and highlight
the correct option. That needs the answer key — but shipping the whole key let a
learner read every answer before starting, and in Sprint 57 the browser computed
the final score itself.

`/api/quiz/check` resolves both: the client submits **one** answer and gets back
only that question's verdict. Feedback stays instant and authoritative, no
un-answered question is exposed, and the persisted score comes from
`/api/quiz-attempts` re-grading the raw answers. A test asserts the response
contains nothing beyond the asked-about question's five fields.

`SingleChoice` and `MultipleChoice` now hold `correctIndex` in local state fed by
the server verdict instead of reading `question.correctIndex`.

### Two more fabricated things deleted

- **`ProgressionMasteryWidget.defaultStats`** — 15 lessons, 84% accuracy, 7-day
  streak, 1540 rating. The component now returns `null` without real stats, so a
  caller that forgets to pass them gets nothing instead of a fictional skill
  profile. `bridgeRating` was removed from `ProgressionStats` entirely; it was
  never rendered.
- **`generateHeatmapData(12)`** (`Math.random()`) — replaced with a real 30-day
  heatmap from the XP event log. `averageThinkingTime: 14.5` became `0`, and
  `bridgeRating: 1540` is gone from the statistics page.

### Duplicate components deleted
